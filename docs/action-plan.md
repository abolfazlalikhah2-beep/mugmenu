# اکشن پلن ماگ‌منو — از طراحی تا کد

مبنای این پلن: MVP اول (منوی عمومی + پنل مدیریت حداقلی + auth + سایت پایه). فاز ۲ و ۳ (تخفیف/گزارشات/پیامک/پرینتر/سوپرادمین) در انتها به‌عنوان روادمپ بعدی آورده شده تا از قلم نیفتن.

---

## اکشن پلن ۱ — Claude Design (فاز UI)

هدف این فاز: رسیدن به یک ست کامل و یکدست از صفحات MVP، آماده برای handoff به کدنویسی. خروجی باید چیزی باشه که بشه مستقیم توصیفش کرد و به Claude Code داد.

### قدم ۰ — Design System (قبل از هر صفحه‌ی جدید)
از چیزی که تا الان ساختی (Login/Register/Menu/Info) یک زبان طراحی مستند کن:
- پالت رنگ: پس‌زمینه سبز گرادیانت، سبز اصلی `#328C3D`، خاکستری‌های متن (`#000`, `#5F5F5F`, `#9F9F9F`, `#A7A7A7`)
- فونت: IRANYekanFN برای فارسی، وزن‌ها (300/400)، انگلیسی برای برندینگ کوچک (NEXT ART / Montserrat)
- شعاع گوشه‌ها: کارت‌های بزرگ ۳۵px، اینپوت‌ها ۱۴px، دکمه‌ها ۱۵-۲۰px
- سایه‌ها: shadow ملایم `0 8px 17.5px rgba(0,0,0,0.04)` برای کارت‌های شناور
- کامپوننت‌های پایه: اینپوت، دکمه اصلی/ثانویه، بج وضعیت (فعال/غیرفعال)، مودال، آیتم لیست با آیکون فعال/غیرفعال
- **این‌ها رو یک‌بار به‌صورت یک صفحه‌ی "Style Guide" جدا طراحی کن** — این سند مرجع تیم کد میشه.

### قدم ۱ — تکمیل منوی عمومی (مشتری نهایی)
اولویت چون ۹۰٪ ترافیک موبایله:
- [ ] صفحه‌ی لیست آیتم‌های یک دسته (گرید/لیست کارت محصول با تصویر، اسم، قیمت، دکمه افزودن)
- [ ] صفحه‌ی جزئیات یک آیتم (تصویر بزرگ، توضیح کوتاه، انتخاب تعداد)
- [ ] سبد خرید / Cart drawer — سه حالت باید در UI افتراق داشته باشن:
  - روی میز: فقط شماره میز + نام + تلفن
  - بیرون‌بر: زمان تحویل تخمینی
  - ارسال با پیک: آدرس + لوکیشن + زمان تحویل
- [ ] صفحه تایید سفارش / رسید نهایی
- [ ] بخش نظرات آیتم (که الان فقط نظرات کلی رستوران رو داری، این سطح آیتم هم لازمه طبق فایل ورد)
- [ ] موبایل هر ۶ صفحه‌ی بالا را اول طراحی کن، دسکتاپ را بعد به‌عنوان breakpoint اضافه کن (نه برعکس)

### قدم ۲ — پنل مدیریت مشتری (نسخه MVP)
فقط این زیرمجموعه، نه کل چیزی که در ورد هست:
- [ ] Dashboard Home: پروفایل کوچک کافه + وضعیت فعال/غیرفعال، ۵ سفارش آخر، نمودار ساده مشتری/سفارش روز
- [ ] منو ▸ محصولات: لیست آرشیو + فعال/غیرفعال + مودال ایجاد/ویرایش (اسم، توضیح تک‌خط، قیمت، عکس، دسته)
- [ ] منو ▸ دسته‌بندی: لیست + مودال ایجاد/ویرایش (اسم، عکس)
- [ ] تنظیمات ▸ تنظیمات فروشگاه: نام، نام انگلیسی، آیدی، آدرس/لوکیشن، ساعت کاری
- [ ] سفارشات ▸ آخرین سفارشات: لیست وضعیت‌دار (جدید/در حال آماده‌سازی/آماده تحویل)
- [ ] ثبت‌نام رستوران‌دار + آنبوردینگ (لوگو، اسم، آیدی، توضیحات، تلفن، آدرس) — قبل از باز شدن پنل

### قدم ۳ — سایت مارکتینگ (نسخه پایه)
**خارج از اسکوپ.** با وردپرس روی دامنه‌ی اصلی ساخته می‌شه، نه در Claude Design/Claude Code.

### قدم ۴ — Handoff checklist (قبل از رفتن سراغ Claude Code)
- [ ] همه صفحات با یک فریم/گرید سایز مشخص (مثلاً موبایل ۳۷۵px و دسکتاپ ۱۹۲۰px مثل نمونه‌های فعلی)
- [ ] Naming یکدست برای هر صفحه (مثل چیزی که در فایل CSS خروجی داری: `Login`, `Register`, `Menu`, `info`)
- [ ] یک سند کوتاه بنویس: هر state چطور تغییر می‌کنه (خالی/پر/خطا/لودینگ) — این جاییه که اکثر پروژه‌ها موقع کد لنگ می‌زنن

## اکشن پلن ۲ — Claude Code (فاز پیاده‌سازی)

شروع این فاز فقط بعد از این‌که Handoff checklist بالا کامل شد.

### قدم ۰ — تصمیمات فنی (قبل از کدنویسی)
- استک پیشنهادی: Next.js (App Router) + Tailwind + shadcn/ui (سازگار با چیزی که خودت هم حدس زدی از رقیب) + دیتابیس Postgres
- تصمیم روی چندمستأجری بودن (multi-tenant): هر رستوران با یک slug (مثل `/demo`, `/baradaran`)؛ همون الگویی که در رقیب هم دیدیم
- انتخاب provider پیامک OTP (برای auth) — این وابستگی بیرونی باید زودتر مشخص و تست بشه چون کل auth بهش گره خورده
- تصمیم هاست/دیتابیس و مدیریت آپلود تصویر (S3-compatible)

### قدم ۱ — Setup و Design Tokens
- [x] Scaffold پروژه + پیاده‌سازی Design System قدم ۰ از فاز طراحی به‌صورت CSS variables / Tailwind config (`app/globals.css`)
- [x] کامپوننت‌های پایه‌ی موجود در Style Guide (Button, Input, Card, StatusBadge, RatingChip/InfoRatingPill, AccordionListItem) پیاده شد — `/style-guide`
- [x] Modal — `BusinessInfoModal` (اطلاعات مجموعه)، در فاز منوی عمومی ساخته شد

### قدم ۲ — Auth (OTP)
- [x] صفحات Login/Register/Forgot/Verification/Change Password (از روی `project/uploads/*.png` بازسازی شد — این‌ها `.dc.html` نداشتن)
- [x] اتصال به provider پیامک — فقط abstract/mock (`lib/auth/otp-provider.ts`)؛ provider واقعی هنوز انتخاب نشده
- [x] مدیریت session/token — کوکی httpOnly (`lib/auth/session.ts`)، login/register/change-password به Postgres واقعی وصله

### قدم ۳ — منوی عمومی (مشتری نهایی) — قلب MVP
- [x] صفحه پروفایل رستوران + دسته‌بندی‌ها (`/[cafeSlug]`, `/[cafeSlug]/menu`)
- [x] لیست آیتم و جزئیات آیتم (`/[cafeSlug]/item/[itemId]`)
- [x] منطق سه‌حالته سفارش (روی میز / بیرون‌بر / ارسال) — متمرکز در `lib/menu/cart-context.tsx` + `lib/menu/actions.ts`
- [x] سبد خرید + ثبت سفارش (بدون درگاه پرداخت واقعی، طبق برنامه) — `/[cafeSlug]/cart` → `createOrder` → `/[cafeSlug]/receipt/[orderId]`
- [x] بخش نظرات آیتم (`/[cafeSlug]/item/[itemId]/reviews`) + خلاصه نظرات در مودال اطلاعات مجموعه

### قدم ۴ — پنل مدیریت مشتری (MVP)
- [x] آنبوردینگ اولیه رستوران‌دار بعد از ثبت‌نام (`/onboarding`)
- [x] Dashboard Home با آمار واقعی از دیتابیس (سفارش/مشتری/درآمد امروز با دلتای دیروز، نمودار زمان شلوغی ۳۰ روز، ۵ سفارش آخر، خلاصه فروش دسته) — `/dashboard`
- [x] CRUD محصولات + دسته‌بندی — `/dashboard/products`, `/dashboard/categories` (آپلود تصویر واقعی هنوز وصل نیست؛ placeholder، طبق برنامه‌ی S3 در فاز بعد)
- [x] تنظیمات فروشگاه — `/dashboard/settings`
- [x] لیست سفارشات + مودال جزئیات/تغییر وضعیت — `/dashboard/orders`, `/dashboard/orders/[orderId]` (به‌روزرسانی با رفرش سمت کلاینت بعد از هر اکشن؛ polling/websocket واقعی هنوز نیست — فاز بعد)

### قدم ۵ — سایت مارکتینگ پایه
**خارج از اسکوپ این ریپو.** تصمیم گرفته شد سایت مارکتینگ (صفحه اصلی، تعرفه‌ها) با وردپرس روی دامنه‌ی اصلی ساخته بشه، نه Next.js. این اپ (auth + منوی عمومی + پنل مدیریت) روی یک ساب‌دامین جدا دیپلوی می‌شه. کاری اینجا لازم نیست.

### قدم ۶ — تست پایلوت
- [ ] یک یا دو رستوران واقعی روی همین نسخه راه بندازی، فیدبک واقعی جمع کنی قبل از رفتن سراغ فاز ۲

### روادمپ فاز ۲ (بعد از پایلوت، بدون طراحی مجدد از صفر)
تخفیف‌ها (دستی+خودکار) · گزارشات تحلیلی · مشتریان · کاربران و نقش‌ها · تیکتینگ سمت مشتری · QR code generator

### روادمپ فاز ۳ (وابسته به زیرساخت بیرونی)
- پنل پیامک کامل (وابسته به قرارداد SMS provider)
- پرینتر لیبل‌زن → نیاز به یک **Local Print Agent** جدا (پروژه‌ی مجزا، نه بخشی از وب)
- درگاه پرداخت + تمدید اشتراک
- پنل مدیریت سوپرادمین (مالی، مشتریان یعنی صاحبان رستوران، کاربران داخلی، تیکتینگ داخلی)

---

### نکته کلی
هر بار که فاز طراحی یک ماژول جدید تموم شد (مثلاً "تخفیف‌ها")، همون Handoff checklist بالا رو براش تکرار کن قبل از این‌که بری سراغ Claude Code — این جلوی رفت‌وبرگشت‌های گنگ بین طراحی و کد رو می‌گیره.
